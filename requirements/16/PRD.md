## 1. 目标与背景

### 1.1 背景

CNN v6（由意图 #15 引入）是一个带 BatchNorm 和残差连接的策略网络，输出 225 维落子概率分布，用于选择下一步落子位置。但它缺少对当前局面的**整体评估能力**——即判断"当前局面有多好、胜率有多高"。

在强化学习训练场景中，一个能评估局面价值（value）的模型有两个核心用途：

1. **辅助局面判断**：在对战和复盘时，可以直观地看到 AI 对当前局面的评估走势
2. **为后续训练提供基础**：价值信号可以作为训练中的辅助监督，提升模型对全局胜负的理解

### 1.2 目标

修改 CNN v6 网络结构，在现有策略头（policy head）基础上，**增加一个并行的价值头（value head）**，使其能同时输出：

- **策略**（不变）：225 维落子概率分布
- **价值**（新增）：一个 [−1, 1] 区间的标量，表示当前落子方的预估胜率

### 1.3 不做的事

- 不修改 CNN v1～v5 的任何代码和权重
- 不修改训练流程（损失函数、样本格式、训练器基类等均不变，后续意图独立处理价值头训练）
- 不修改 CNN v6 的策略头结构（Conv_out、Flatten、LogSoftmax 不变）
- 不修改模型的文件存储路径和 save/load 的文件格式兼容性（新旧权重不兼容属于预期行为）

## 2. 范围与边界

### 2.1 功能范围

| 编号 | 功能 | 说明 |
|------|------|------|
| FR-1 | 新增价值头分支 | 在 CNN v6 网络的 Flatten 之后、与 LogSoftmax 并行，增加 FC(225→1) + Tanh，输出价值标量 |
| FR-2 | 修改 forward 返回值 | 网络 forward 同时返回策略（225 维 log-probability）和价值（标量） |
| FR-3 | 修改 predict 接口 | `predict()` 返回值从 `List[float]` 变为 `(List[float], float)` 元组 |
| FR-4 | 适配调用方 | 所有调用 `predict()` 的代码解包新返回格式 |
| FR-5 | 新增测试用例 | 测试价值头结构、输出值域、predict 接口变更（§5） |

### 2.2 边界

- **仅修改 CNN v6**：其他模型（v1～v5、FCv1、Random）保持不变
- **仅修改网络结构**：不涉及训练器、损失函数、样本格式的改造
- **接口变更范围**：`predict()` 返回格式变更，需要同步修改所有调用方
- **权重不兼容**：新网络结构增加的 FC 层参数导致旧 `.pth` 文件和当前结构不匹配，加载旧权重会失败

## 3. 术语定义

| 术语 | 定义 |
|------|------|
| 策略头 (Policy Head) | 网络的输出分支之一，输出 225 维落子概率分布（LogSoftmax），表示在每个空位上落子的优先程度 |
| 价值头 (Value Head) | 网络的输出分支之一，输出一个标量值，表示对当前局面的胜负评估 |
| 价值 (Value) | 一个 [−1, 1] 区间的标量，从**当前落子方视角**评估局面胜率：+1 表示当前方必胜，−1 表示当前方必败，0 表示均势 |
| Tanh | 双曲正切激活函数，将任意实数值映射到 (−1, 1) 区间 |

## 4. 功能说明

### 4.1 网络结构变更

#### 4.1.1 变更前后对比

**变更前**（CNN v6 原有结构）：

```
输入: (batch, 3, 15, 15)
  → Conv1 + BN → ReLU
  → [残差块 1] → ReLU
  → [残差块 2] → ReLU
  → Conv_out (32→1, 1×1)
  → Flatten → 225
  → LogSoftmax → 策略 (batch, 225)
```

**变更后**（新增价值头）：

```
输入: (batch, 3, 15, 15)
  → Conv1 + BN → ReLU
  → [残差块 1] → ReLU
  → [残差块 2] → ReLU
  → Conv_out (32→1, 1×1)         ← 不变
  → Flatten → 225                 ← 不变
      ├─ LogSoftmax → 策略 (batch, 225)     [原有策略头]
      └─ FC(225→1) → Tanh → 价值 (batch, 1)  [新增价值头]
```

> 价值头在 Flatten 之后与 LogSoftmax **并行分支**，共享 Conv_out 提取的 225 维空间特征。

#### 4.1.2 价值头详述

| 属性 | 说明 |
|------|------|
| 输入 | Flatten 后的 225 维向量 |
| 结构 | 全连接层 FC(225→1) |
| 激活函数 | Tanh |
| 输出 | 标量，值域 [−1, 1] |
| 语义 | 当前落子方的预估胜率（+1 必胜，−1 必败，0 均势） |
| 输出形状 | 训练时为 (batch, 1)，推理时（predict 调用）压缩为单个 float |

#### 4.1.3 参数量变更

| 组件 | 新增参数量 |
|------|----------|
| FC(225→1) 权重 | 225 |
| FC(225→1) 偏置 | 1 |
| **合计新增** | **226** |

变更后 CNN v6 总参数量约 **38,467**（原 38,241 + 新增 226）。

### 4.2 模型接口变更

#### 4.2.1 predict()

| 属性 | 变更前 | 变更后 |
|------|--------|--------|
| 返回值类型 | `List[float]` | `(List[float], float)` |
| 返回值含义 | 225 维落子概率分布 | 元组 (策略概率列表, 价值标量) |
| 策略部分 | 225 维，值域 (0, 1)，总和 ≈ 1 | **不变** |
| 价值部分 | 无 | 1 个 float，值域 [−1, 1] |

#### 4.2.2 其他接口

| 接口 | 变更 |
|------|------|
| `save(model_path)` | **不变**。state_dict 自动包含新增 FC 层参数 |
| `load(model_path)` | **不变**。但旧权重文件（无 value_fc 参数）加载会失败 |
| `name` | **不变**。仍返回 `"cnn_v6"` |
| `full_name` | **不变**。仍返回 `"cnn_v6.N"` |

### 4.3 受影响的调用方

以下文件/模块中调用了 `predict()`，需适配新的元组返回格式：

| 调用方 | 说明 |
|--------|------|
| game engine（`ai/engine.py`） | AI 落子决策使用 predict 结果 |
| battle（`ai/battle.py`） | AI 对战使用 predict 获取落子概率 |
| evaluator（`ai/evaluator.py`） | 样本评估使用 predict 结果 |
| GUI（`gui/` 相关文件） | 界面显示（热力图等）使用 predict 结果 |
| 测试文件 | 测试中调用 predict 并验证输出 |

## 6. 约束与注意事项

1. **旧权重不可用**：新增 FC(225→1) 后，网络 state_dict 中多出 `value_fc.weight` 和 `value_fc.bias` 两个 key，CNN v5 及旧 CNN v6 的权重文件无法加载
2. **推理模式**：predict 调用时价值头不依赖 BN 的 batch 统计量，但仍需确保网络处于 eval 模式（由基类 predict 自动设置）
3. **值域语义固定**：价值始终从**当前落子方视角**表达，+1 = 当前方必胜，−1 = 当前方必败。即使在对战过程中切换落子方，也不改变此语义
4. **FC 层命名**：新增 FC 层建议命名为 `value_fc`，以便 state_dict 中与策略相关层明显区分
5. **策略头完全保留**：LogSoftmax 输出的 policy 部分行为和语义与变更前完全一致
6. **CNN v5 不受影响**：本需求不修改 CNN v5 及之前模型的任何代码和权重
