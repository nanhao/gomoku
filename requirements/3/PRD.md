# PRD: create_samples 新增 --sample_games 参数

## 1. 元信息

| 项目       | 值                                       |
| ---------- | ---------------------------------------- |
| intention_id | 3                                      |
| 目标模块   | `ai/create_samples.py`                   |
| 文档版本   | v1.0                                     |
| 创建日期   | 2026-06-05                               |

---

## 2. 目标与背景

### 2.1 现状

当前 `ai/create_samples.py` 通过 `--games N` 参数指定自对弈局数。脚本执行固定 N 局对弈后，再经 `should_keep_game` 过滤生成训练样本。

### 2.2 问题

当启用单方温度采样（`--temp-side black/white`）时，约 50% 的对局因贪婪方获胜被过滤丢弃。用户指定 `--games 100`，实际可能只得到约 50 局可用样本。用户无法预知需要多少局原始对弈才能收集到期望数量的有效样本。

### 2.3 目标

新增 `--sample_games` 参数，让用户直接指定**期望收集的可用样本局数**，脚本持续自对弈直到达标，消除过滤率不确定性带来的困扰。

---

## 3. 范围与边界

### 3.1 范围内

- 在 `ai/create_samples.py` 的 CLI 参数中新增 `--sample_games`
- `--sample_games` 与 `--games` 互斥，不可同时指定
- 脚本持续自对弈，直到收集到指定数量的可用样本局后停止
- 10% 间隔的进度输出
- Ctrl+C 优雅退出并保存已收集数据
- 验收工具 `tools/create_samples_tool/` 同步支持 `--sample_games` 参数

### 3.2 范围外

- 不修改 `AIGameManager`、`SampleCreator`、`should_keep_game` 等模块的核心逻辑
- 不新增 `--max-games` 等安全上限参数（依赖 Ctrl+C 中断）
- 不修改 `self_play_generator.py`（该模块服务于训练循环，不直接暴露此参数）
- 不修改 `app.py` 和 `data_parser.py`（API 接口层无需变更，仅透传参数）

---

## 4. 术语定义

| 术语       | 定义                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 样本局     | 经过 `should_keep_game` 过滤且不是平局的对局，即实际可用于生成训练样本的对局 |
| 原始对局   | 脚本执行的自对弈对局总数（含被过滤丢弃的对局）                             |
| 过滤率     | 原始对局中被丢弃的比例，取决于温度采样模式                               |

## 5. 功能说明

### 5.1 新增参数 --sample_games

| 属性     | 值                                                    |
| -------- | ----------------------------------------------------- |
| 参数名   | `--sample_games`                                      |
| 类型     | 正整数（> 0）                                         |
| 必填     | 否（与 `--games` 二选一）                             |
| 默认值   | 无                                                    |
| 互斥     | 与 `--games` 互斥，同时指定时脚本报错退出             |
| 语义     | 持续自对弈，直到收集到指定数量的样本局后停止          |

### 5.2 互斥校验

- 同时指定 `--games` 与 `--sample_games` 时，脚本输出错误信息并以非零退出码退出
- 两者都不指定时，保持当前默认行为（`--games 100`）

### 5.3 停止条件

当满足以下任一条件时停止对弈：

1. **达标停止**：已收集的样本局数 >= `--sample_games` 指定值
2. **用户中断**：用户按 Ctrl+C，触发优雅退出

### 5.4 样本局计数规则

每局对弈结束后，依据以下规则判定该局是否计入样本局：

1. 对局有明确胜方（非平局、非未结束）
2. 通过 `should_keep_game` 过滤（非单方采样模式下全部保留；单方采样模式下仅采样方获胜保留）

两个条件均满足时，样本局计数 +1。

### 5.5 进度输出

- 每当样本局计数达到目标的 10%、20%、…、100% 时，打印进度信息
- 进度信息包含：当前样本局数/目标样本局数、已完成原始对局数、当前百分比
- 最后一局达标时也必须打印 100% 进度

### 5.6 Ctrl+C 优雅退出

- 用户按 Ctrl+C 时，脚本停止后续对弈
- 已完成的对局数据正常保存
- 已达标的部分样本正常生成并写入输出文件
- 打印中断统计：已完成原始对局数、已收集样本局数、达标百分比

### 5.7 最终输出

`--sample_games` 模式下的最终输出与 `--games` 模式一致，额外增加原始对局数信息：

```
样本生成完成:
  对局数:     <原始对局总数>
  样本局数:   <过滤后保留的对局数>
  数据增强:   启用 (8 变换) / 禁用
  样本数:     <最终样本条数>
  输出路径:   <输出文件路径>
```

### 5.8 验收工具更新

验收工具 `tools/create_samples_tool/` 需同步支持 `--sample_games` 参数，涉及以下文件：

#### 5.8.1 executor.py — build_cli_command 变更

在 `build_cli_command()` 中新增 `sample_games` 参数处理：

- 当 `params` 中包含 `sample_games` 键且值非空时，追加 `--sample_games <value>` 到命令参数
- 当 `sample_games` 有值时，不追加 `--games` 参数（互斥）
- 当 `sample_games` 无值或不存在时，保持原有 `--games` 行为

#### 5.8.2 index.html — 表单新增 sample_games 输入框

在 `games` 输入框下方新增 `sample_games` 输入框，标签为 `sample_games`，类型 number，placeholder 为 `可选，目标样本局数`。

互斥交互规则（双输入框互斥方案）：
- 用户在 `games` 输入框中输入值时，自动清空 `sample_games` 输入框
- 用户在 `sample_games` 输入框中输入值时，自动清空 `games` 输入框
- 两个输入框都不填时，后端默认 `--games 100`（与 CLI 行为一致）

#### 5.8.3 app.js — collectParams 变更

在 `collectParams()` 中新增 `sample_games` 字段：
- 从 `sampleGamesInput` 读取值，为空时传 `null`
- `games` 字段从 `gamesInput` 读取，为空时传 `null`（而非默认 100，由 CLI 侧兜底）

新增 `input` 事件监听：
- `gamesInput` 的 `input` 事件 → 清空 `sampleGamesInput`
- `sampleGamesInput` 的 `input` 事件 → 清空 `gamesInput`

#### 5.8.4 不变更的文件

| 文件 | 原因 |
|------|------|
| `app.py` | API 层仅透传 params 到 executor，无需变更 |
| `data_parser.py` | 数据解析逻辑与对局模式无关 |
| `style.css` | 新增输入框复用现有 `.param-row` 样式 |

## 6. 命令行用法示例

```
# 使用 --sample_games（持续对弈直到收集 100 局样本）
python ai/create_samples.py --model cnn_v3.1 --sample_games 100 --output ai/train_data/win_samples.json

# 使用 --games（现有行为，固定 100 局对弈）
python ai/create_samples.py --model cnn_v3.1 --games 100 --output ai/train_data/win_samples.json

# 互斥错误
python ai/create_samples.py --model cnn_v3.1 --games 100 --sample_games 100 --output ai/train_data/win_samples.json
# 输出: 错误: --games 和 --sample_games 不能同时指定
```

## 8. 约束与注意事项

1. **互斥硬约束**：`--games` 与 `--sample_games` 不可同时指定，违反时脚本必须报错退出
2. **不修改下游模块**：`AIGameManager`、`SampleCreator`、`should_keep_game` 等模块的接口和行为不变
3. **样本局计数一致性**：`--sample_games` 模式下的样本局判定逻辑必须与现有 `SampleCreator` + `should_keep_game` 的联合过滤逻辑一致，避免同一对局在计数时保留、生成样本时被丢弃的不一致
4. **验收工具互斥前端兜底**：UI 双输入框互斥清空仅为用户友好提示，后端 `build_cli_command` 必须独立校验互斥（防御前端绕过）
