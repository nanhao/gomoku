# 模型输出向量从 675 维改为 225 维

## 1. 需求内容

用户发现模型层的输出向量设计存在错误：原设计为 675 维（格式：`[x, y, reward] * 225`，即每个落子位置携带坐标和奖励值），但坐标信息是冗余的，因为位置与索引的映射关系是固定的（索引 i → 位置 `(i//15, i%15)`），不需要在输出中重复携带坐标。

**变更要求**：将模型输出向量从 675 维改为 225 维，每个元素直接对应棋盘某位置的 reward 值。

具体任务：
1. 修改设计文档体现这个变更
2. 更新测试用例体现这个变更
3. 修改代码实现这个变更
4. 回归测试

## 2. 解决思路

- **旧格式（675维）**：`[x0, y0, reward0, x1, y1, reward1, ..., x224, y224, reward224]`（交错排列），reward 的索引为 `3*i+2`
- **新格式（225维）**：`[reward(0,0), reward(0,1), ..., reward(14,14)]`，索引 i 对应位置 `(i//15, i%15)`，直接用索引访问

影响范围：
- 接口文档：`design/ai_design.md`、`ai/base_model.py`
- 具体实现：`ai/random/model.py`、`ai/fc_v1/model.py`（输出层维度）
- 解析逻辑：`ai/engine.py`（从 reward 列表选择落子位置）
- 训练器：`ai/fc_v1/trainer.py`（loss 计算、张量准备）
- 样本生成：`ai/evaluator.py`（output/mask 向量生成）
- 测试文件：`tests/ai/` 目录下所有相关测试

## 3. 执行过程

### 步骤一：修改设计文档

修改 `design/ai_design.md`：
- 更新 `BaseModel.predict()` 返回值说明（675→225）
- 更新 `RandomModel` 代码框架中的 predict 实现
- 更新 `AIEngine` 解析逻辑（步长3遍历 → 索引映射）
- 更新文档中的测试用例断言

### 步骤二：修改代码实现

| 文件 | 修改内容 |
|------|---------|
| `ai/base_model.py` | 更新 predict() docstring：返回225维 |
| `ai/random/model.py` | predict() 从生成 [x,y,0] 改为 `return [0] * 225` |
| `ai/engine.py` | 解析循环从步长3改为 `for i in range(225): x=i//15, y=i%15` |
| `ai/fc_v1/model.py` | 输出层 `nn.Linear(1000, 675)` → `nn.Linear(1000, 225)`；predict() 直接 append reward |
| `ai/evaluator.py` | `_initialize_sample` 用225维；`_compute_rewards` 直接计算 `reward_idx = pos[0]*15+pos[1]`；删除 `_find_reward_index` 方法 |
| `ai/fc_v1/trainer.py` | `_compute_loss` 改为直接索引 `estimated[i]`；`_prepare_tensors` 不再扩展到675维；`_masked_loss` 参数适配 |

### 步骤三：更新测试用例

| 测试文件 | 修改内容 |

### 步骤四：解决兼容性问题

**问题**：旧的 `ai/fc_v1/fc_v1.pth` 文件是675维模型，加载到新的225维网络时报错：
```
RuntimeError: size mismatch for fc_output.weight: copying a param with shape torch.Size([675, 1000]) from checkpoint, the shape in current model is torch.Size([225, 1000])
```

**解决方案**：运行以下命令重新生成225维模型：
```python
from ai.fc_v1.model import FCv1Model
m = FCv1Model(fresh=True)
m.save()
```

### 步骤五：修复 TestFCv1TrainerVerboseOutput 的遗留 675 维引用

在上下文切换后发现 `test_fc_v1_trainer.py` 中 `TestFCv1TrainerVerboseOutput` 类的两处 `_create_test_sample` 方法（第441行和第530行）仍然使用 `[0]*675`，导致训练时维度不匹配。修复后所有测试通过。
