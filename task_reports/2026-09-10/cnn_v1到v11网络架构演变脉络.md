# 五子棋 CNN 模型演变脉络梳理（cnn_v1 → cnn_v11）

> 整理日期：2026-09-10
> 信息来源：`design/` 设计文档、`intention/intention.md`（各版本第一手动机记录）、`src/ai/models/cnn_v*/model.py`（代码实现）、git 提交历史、`task_reports/` 历史缺陷报告

---

## 1. 总览

**演变主线一句话**：从"与全连接模型对标的轻量策略网络"出发 → 结构极简化实验 → 深度堆叠与残差化 → 引入价值头拥抱 AlphaGo Zero（下称 AGZ）范式 → 容量扩张 → 两次路线试错（放弃 MCTS、放弃策略头）→ 最终回归 AGZ 本源：大容量残差双头网络 + 强训练基础设施。

### 1.1 版本总览表

| 版本 | 创建时间 | 关联意图 | 核心结构变化 | 参数量 | 驱动原因 |
|------|---------|---------|-------------|--------|---------|
| cnn_v1 | 2026-04-04 | — | 3 层卷积（3→32→64→128）+ 2 层 FC，单策略头 LogSoftmax | ~445 万 | 与 FC v1 参数量对齐，公平对比 |
| cnn_v2 | 2026-04-24 | — | 通道统一 64，FC1 从 28800→150 压缩为 14400→64 | ~101 万 | FC1 独占 97% 参数，是训练速度瓶颈 |
| cnn_v3 | 2026-04-28 | — | 纯卷积 3 层（32 通道，无 BN）+ 1×1 卷积直出，无 FC | ~1.9 万 | 极简结构实验；1×1 卷积替代 FC |
| cnn_v4 | 2026-06-16 | #11 | v3 + 1 层 32 通道卷积（共 4 层） | ~2.8 万 | 逐层加深探索 |
| cnn_v5 | 2026-06-18 | #14 | v4 + 1 层（共 5 层） | ~3.8 万 | 继续加深探索 |
| cnn_v6 | 2026-06-22 | #15 | 引入 BatchNorm + 2 个残差块（层重组，规模不变） | ~3.8 万 | 深度增加后稳定训练、保证梯度流动 |
| cnn_v7 | 2026-06-22 | #16/17/24/36/37 | v6 + 价值头 → 双头输出；后改相对视角编码 | ~3.85 万 | AGZ 范式：MCTS 需要价值头做叶节点评估 |
| cnn_v8 | 2026-07-14 | #40 | 策略头/价值头各加一层 FC(64) 隐藏层 | ~8.2 万 | AGZ 从零训练噪音大，模型太小"学不动"，训练停滞 |
| cnn_v9 | 2026-07-22 | #42 | 所有卷积通道 32→48 | ~12.8 万 | 继续扩容，提升特征提取能力 |
| cnn_v10 | 2026-07-28 | #43/44 | v9 去掉策略头，仅保留价值头 | ~10 万 | 判定 MCTS 策略头学不会，改走"枚举-评估"路线 |
| cnn_v11 | 2026-08-04 | #45 | v9 基座：7 个残差块 + 256 通道 + AGZ 论文结构双头 | ~843 万 | 回归 AGZ 本源，大容量 + C++ MCTS 基础设施 |

### 1.2 三条贯穿始终的演变线

| 维度 | 演变轨迹 |
|------|---------|
| **输入编码** | v1~v6 绝对视角（黑棋位/白棋位/当前方 3 通道）→ v7 起相对视角（我方棋子/对方棋子/我方颜色，AGZ 风格，颜色互换不变）。编码语义变更与旧权重不兼容，切换需 `fresh=True` 从零训练 |
| **输出结构** | v1~v6 单策略头（225 维概率）→ v7/v8/v9 双头（策略 + 价值 [-1,1]）→ v10 单价值头（试错）→ v11 回归双头 |
| **训练范式** | 人工棋谱/传统评估样本 + KL 散度（v1~v6）→ AGZ MCTS 自对弈 + 双头损失 `l = (z−v)² − πᵀp_log`（v7 起）→ + C++ MCTS 并行生成 + 样本缓冲区 + 晋升机制 + 人类棋谱 off-policy 监督（v11 时代） |

## 2. 阶段一：对标 FC 的入门 CNN（cnn_v1，2026-04-04）

### 背景

项目最早的 AI 模型是全连接网络 FC v1（约 445 万参数）。CNN v1 的设计目标（`design/cnn_design.md`）明确写着：**参数量控制在 ~400 万，与 FC v1 相当，适合公平对比两种模型的效果**——这是一个"卷积 vs 全连接"的对照实验。

### 网络结构

```
输入 (batch, 3, 15, 15)   ← 绝对视角 3 通道：黑棋位置 / 白棋位置 / 当前落子方
→ Conv(3→32) → BN → ReLU
→ Conv(32→64) → BN → ReLU
→ Conv(64→128) → BN → ReLU
→ Flatten (28800) → FC(150) → ReLU → FC(225) → LogSoftmax
```

输出为 225 维 log-probability 分布，本质是**纯策略网络**（预测每个落子位置的概率）。

### 同期训练基础设施演变（服务于 v1~v3 的迭代）

- 损失函数从 L1 全面改为 KL 散度（intention #4）
- mini-batch 训练模式、每 200 epoch 打印 loss、训练奖励归一化等（`task_reports/2026-04-03`）
- 学习率参数化（intention #7）与《学习率分析与优化建议书》（`design/learn_rate/`）：诊断出固定学习率 0.001 在训练后期导致梯度震荡，引入学习率衰减与梯度裁剪思路

## 3. 阶段二：参数压缩与极简实验（cnn_v2、cnn_v3）

### cnn_v2（2026-04-24）：砍掉 FC 瓶颈

**动机**（`design/cnn_v2_design.md`）：v1 实际训练 2000 epoch 耗时较长，诊断发现 FC1 层（28800→150）独占 432 万参数（占总参数 97%），是计算瓶颈。

**变化**：卷积通道统一为 64（Conv1 3→64），Flatten 从 28800 降到 14400，FC1 压缩为 14400→64。总参数量 445 万 → 101 万（**-77%**），在保持卷积特征提取能力不变的前提下大幅缩短训练时间、降低内存。

### cnn_v3（2026-04-28）：纯卷积极简实验

**动机**（`design/cnn_v3_design.md`）：探索"最简网络"在五子棋任务上的学习能力——去除全部 FC 层、BN 层，用 **1×1 卷积（仅 33 个参数）替代 FC**，全程保持 15×15 空间结构，天然适配棋盘布局。

**变化**：3 层卷积统一 32 通道（无 BN）→ Conv1×1(32→1) → Flatten → LogSoftmax。参数量仅 **1.9 万**（v2 的 1.9%）。

**深远影响**：这一"1×1 卷积直出 15×15 空间概率图"的输出方式被后续所有版本继承（v4~v10 一直保留，v11 演化为 AGZ 风格 2 通道策略头）。

### 附属演变：多代模型机制（v3 起引入）

自 cnn_v3 开始，注册表标记 `supports_multi_gen=True`（v1/v2 为 False），引入 `cnn_v3.1`、`cnn_v3.2` 式的"代数"概念，支撑 `iterative_train.py` 的"自对弈生成样本 → 训练新一代 → 新旧对战评估 → 胜率达标晋升"迭代闭环（intention #6/#12/#13/#22）。这是后来所有版本沿用的自我迭代训练框架的雏形。

### 重要教训：v3 的 ReLU 梯度消失死网络（2026-06-06）

`task_reports/2026-06-06/bug_report_cnn_v3_relu_gradient_vanishing.md` 记录：训练 `cnn_v3.5` 时 300 个 epoch loss 完全水平、grad_norm 恒为 0、输出恒为均匀分布。根因是**实现的 bug 而非设计问题**：`conv_out` 与 LogSoftmax 之间多插了一个 ReLU。随机初始化一旦 225 个位置输出全为负值，ReLU 将其全部清零 → LogSoftmax 收到全零向量 → 输出均匀分布 → ReLU 局部梯度为 0 → 整个网络的梯度链被切断，成为"死网络"（是否触发取决于初始化运气）。

修复为 1×1 卷积直接接 LogSoftmax。此后 **v4/v5 的 `model.py` 中都固化了同一段注释**："此处不加 ReLU，否则初始化不当会导致所有输出为负值……模型不学习"——一个由真实事故沉淀为编码规范的经验。

## 4. 阶段三：深度堆叠与残差化（cnn_v4、cnn_v5、cnn_v6）

### cnn_v4（intention #11）/ cnn_v5（intention #14）：逐层加深

两个意图的描述都非常直白："在 cnn_v3（v4）的基础上增加一个 32 通道隐藏层，其他保持一致"。这是典型的**逐步加深实验**：v3 只有 3 层卷积（1.9 万参数）表达力可能不足，于是 v4 加到 4 层（2.8 万）、v5 加到 5 层（3.8 万），每一步只动一个变量，保持输入编码、1×1 直出、LogSoftmax 全部不变。

### cnn_v6（intention #15）：BN + 残差化

**动机**：在 v5 的五层纯卷积基础上引入 BatchNorm 与残差连接——把第 2/3 层卷积重组为残差块 1、第 4/5 层重组为残差块 2，每层 Conv 后加 BN（Conv→BN→ReLU）。**层数与通道数不变**（参数量几乎不变，~3.8 万），变的只是"怎么训"。

**设计决策记录**（`design/15/main_docs/main_design.md`）：

| 决策 | 理由 |
|------|------|
| BN 置于 Conv 后、ReLU 前 | 业界标准做法 |
| 残差 shortcut 加在第二个 BN 后、ReLU 前 | 标准 Pre-activation 残差块变体，加法在归一化后进行 |
| shortcut 恒等直连、无 1×1 投影 | padding=1、stride=1、通道不变，形状天然一致 |
| 残差块内联实现、不封装子模块 | v6 仅此一处使用，避免不必要接口（v11 时改为 ResBlock 类封装） |

**阶段小结**：v4→v5 回答"加深有没有用"，v6 回答"加深之后怎么训得稳"——残差连接保证梯度经恒等通路直达浅层，BN 稳定各层分布。这两者与 v3 ReLU 事故共同构成项目早期"训练稳定性"主题的完整拼图。

## 5. 阶段四：双头转型，拥抱 AGZ 范式（cnn_v7）

cnn_v7 是整个演变史上**范式转折点**，其形成经历了"加头实验 → 独立成版 → 价值头两轮改造 → 编码与训练体系整体切换"四步。

### 5.1 从实验到独立版本（intention #16 → #17）

- **intention #16**：先直接修改 cnn_v6，在 flatten 后增加价值头（FC → Tanh，输出 [-1,1] 标量胜率）——这是价值头的第一次实验。
- **intention #17**：实验验证方向可行后，决定**恢复 cnn_v6 为单头策略网络，把双头版本独立为 cnn_v7**，保持"一个版本一个结构"的版本管理原则。对应 git 提交（2026-06-22）："feat: 新增 cnn_v7 双头模型，恢复 cnn_v6 为单头策略网络"。

### 5.2 价值头的两轮改造（intention #36 → #37）

| 轮次 | 结构 | 价值头参数 | 备注 |
|------|------|-----------|------|
| 初版（#16） | flatten(225) → FC → Tanh | — | 直接挂在策略输出后 |
| 加隐藏层（#36） | flatten → FC(225→128) → ReLU → FC(128→1) → Tanh | 29,057 | 对应 `design/cnn_v7_architecture.puml` 中绘制的形式 |
| 轻量化（#37） | 独立 value_conv_out(32→1, 1×1) → flatten → ReLU → FC(225→1) → Tanh | **259** | 从 conv_out **之前**的共享特征分支，参数量 **↓112×**，即当前代码形态 |

intention #37 的原话："I think the fc layers of the value head takes two many parameters. I prefer to … make the value head branches from before the cnnv_out"——用另一个 1×1 卷积从共享特征直接提取价值特征，替代臃肿的 FC 塔。这一"价值头独立 1×1 分支 + 极小 FC"形态一直沿用到 v9/v10。

### 5.3 相对视角编码 + AGZ MCTS 训练体系（intention #24，2026-06-24）

`design/24/main_docs/main_design.md`（AlphaGo Zero MCTS 训练体系，关联模型 cnn_v7）完成了三项关键切换：

1. **输入编码**：绝对视角 → 相对视角（通道 0=我方棋子、1=对方棋子、2=我方颜色），获得颜色互换不变性。⚠️ 与旧绝对编码权重不兼容，必须 fresh 重训。
2. **MCTS 搜索**：选择阶段用策略头输出作为 PUCT 先验 P，模拟/评估阶段直接用价值头输出替代随机走子——即 AGZ 的两点核心改造。
3. **训练数据与损失**：样本改为 `(state, π, z)`——π 是 MCTS 归一化访问计数分布，z 是对局结果（胜 +1/负 −1/平 0）；损失函数 `l = (z−v)² − πᵀp_log`（MSE + CrossEntropy），正则用 AdamW `weight_decay=1e-4`（参照 AGZ 论文惯例）。

**新旧体系刻意隔离**：新建 `DualHeadTrainer`（v7 专用），旧 `BaseTrainer`（KL 散度、单策略头）保留继续服务 cnn_v1~v6；`board_vector_to_cnn_tensor`（绝对编码）不删除。训练配套还有 MCTS 搜索全流程 JSON 日志（可逐 simulation 复现校验）、自对弈与训练脚本分离。

## 6. 阶段五：容量扩张（cnn_v8、cnn_v9）

### cnn_v8（intention #40，2026-07-14）：小模型学不动噪音

这是 intention.md 中动机写得最透彻的一条，原文：

> "测试了屏蔽 value 网络、屏蔽 policy 网络、调大 mcts 评估次数和 batch，感觉还是网络太小支持不了。因为 agz 的方法是从零开始训练，会有很多噪音，模型太小无法从噪音里面去识别出有效信息，训练就停滞。所以决定还是要扩展模型规模和调整训练节奏。"

**变化**：在 v7 基础上，策略头与价值头在 flatten 后各加一层 FC(64) 隐藏层，参数量 3.85 万 → **8.2 万**（2.1×）。共享卷积体不变——扩容先从决策头开始。

**同期工程妥协**：因训练太耗时，MCTS 做退化处理（batch=225、每步搜索 225 次、落子依据平均奖励 q 而非访问计数 N），优先保证数据吞吐。

### cnn_v9（intention #42，2026-07-22）：通道扩容

继续扩容路线：所有卷积通道 32→**48**，参数量 **~12.8 万**（v8 的 1.56×）。结构（残差块数、双头形态）完全不动，只提升特征图宽度——特征提取能力是当时的瓶颈判断。

## 7. 阶段六：路线试错——放弃策略头（cnn_v10）

### 7.1 动机：对 MCTS 范式的否定（intention #43 原话）

> "经过研究，发现 mcts 机制不适合我的五子棋。因为策略头学不会。一开始随机对弈，产生的策略头样本质量很差，前中期全部是噪音，而最后一步却是接近 one-hot。所以我想改变策略了。"

诊断逻辑：AGZ 策略头要拟合的 π 来自 MCTS 搜索，但自对弈初期模型太弱，MCTS 搜出的 π 前中期近乎噪音、终局步却接近 one-hot，策略头无从学习。

### 7.2 结构与玩法切换

- **网络**：cnn_v10 = cnn_v9 **删掉整个策略头**（conv_out + 两个 policy FC + LogSoftmax），仅保留共享卷积体（48 通道、2 残差块）+ 价值头，参数量约 10 万（设计文档估算；`model.py` docstring 标注 7 万，两者不一致，以设计文档为准）。
- **落子算法**：新增 `ValueOnlyAiEngine` 实现五步"枚举-评估"：①排除孤立空位（8 方向 2 格内无子）→ ②逐空位模拟落子、终局直接判定 ±1/0 → ③剩余局面送价值网络批量评估并取反回当前视角 → ④全盘 masked softmax 归一化 → ⑤argmax/温度采样落子。即**用"价值网络给每个候选局面打分"替代 MCTS 搜索**。

### 7.3 训练与失败（intention #44 附加记录）

价值头专用训练闭环很快跟上（`design/44`：`value_self_play.py` + `CNNV10Trainer`（MSE）+ `value_train.py`，样本仅 `state + z`）。但结果（intention #44 原文）：

> "结果一训练，还是策略崩溃，根本连随机都完全打不过。分析了原因发现 value 被放大。"

**教训**：没有策略先验的纯价值"枚举-评估"路线在该任务上无法收敛——价值网络单独承担全部决策信号时训练不稳定。这条失败记录直接决定了 v11 的方向：**回到双头**。

## 8. 阶段七：回归 AGZ 本源（cnn_v11，2026-08-04）

### 8.1 设计（intention #45 与 `design/45`）

> "新增 cnn_v11，回到双头结构。cnn_v11 是在 cnn_v9 的基础上……"

| 组件 | cnn_v9 | cnn_v11 | 变化理由 |
|------|--------|---------|---------|
| 残差塔 | 2 个残差块 | **7 个残差块**（共 1+7×2=15 层卷积） | 加深以增强特征提取 |
| 通道数 | 48 | **256** | 大幅扩容 |
| 策略头 | conv(48→1) → FC(225→64) → FC(64→225) | **conv(256→2, 1×1) → BN → ReLU → FC(450→225) → LogSoftmax** | 严格对齐 AGZ 论文：2 通道空间特征 + 单 FC、无中间隐藏层——256 通道共享特征已提供足够非线性，头保持简洁 |
| 价值头 | FC 隐藏层 64（可配置 hidden_size） | conv(256→1) → BN → ReLU → FC(225→**256**) → ReLU → FC(256→1) → Tanh | 固定 256、移除可配置性，参照 AGZ 固定结构避免超参搜索 |
| 参数量 | ~12.8 万 | **~843 万（66×）** | 卷积体占 98%，训练显存主要消耗在 15 层 256 通道特征图 |

工程上完全复用既有基础设施：`DualHeadTrainer`、`PolicyValueAiEngine`、`MCTSSearcher`，仅新增模型包 + registry 一行，自对弈/训练/对战脚本经 registry 自动兼容。相对视角编码与 v7~v10 一致。

### 8.2 配套训练基础设施的大跃进（intention #46~#60）

v11 的成功不只靠网络，同期把训练闭环全面重写为高性能版本：

| 意图 | 内容 |
|------|------|
| #46 | **C++ 实现 MCTS**（LibTorch 加载 TorchScript 权重）：多线程搜索 + 独立 GPU 线程攒批推理，替代 Python 版 |
| #47/#48 | n 层并行自对弈（全局线程池 + GPU 评估）、GPU 推理滑动窗口统计 |
| #49 | **样本缓冲区**：FIFO 8 万条、每 10 层落盘、D4 群 8 变换（旋转+镜像）数据增强 |

## 9. 演变规律与经验总结

### 9.1 驱动因素归类

1. **效率驱动**（v2）：参数分布诊断 → 砍 FC 瓶颈，训练提速是早期第一诉求。
2. **表达力探索**（v3~v5）：极简实验 → 逐层加深，单变量步进。
3. **训练稳定性驱动**（v3 修复、v6）：ReLU 梯度消失事故与残差/BN 的引入，都是"让网络能学"先于"让网络学得好"。
4. **范式驱动**（v7、v10）：v7 拥抱 AGZ（双头 + 相对编码 + MCTS 闭环），v10 试图抛弃 MCTS（纯价值枚举-评估）——范式判断比结构调整影响更大。
5. **容量驱动**（v8/v9/v11）："AGZ 从零训练噪音大，小模型识别不出有效信息"→ 三轮扩容（头 → 通道 → 深度+通道）。
6. **试错回摆**（v10 → v11）：纯价值路线崩溃后回归双头 MCTS，并以更大模型 + 更强基础设施重整旗鼓。

### 9.2 值得沉淀的教训

- **LogSoftmax 之前严禁 ReLU**：随机初始化下可能全零化 → 梯度链断裂成死网络，且症状隐蔽（loss 恒定、grad_norm=0）。已固化为 v4+ 代码注释。
- **从零自博弈的 AGZ 需要匹配的模型容量**：容量不足时训练停滞，扩容顺序为"决策头 → 通道 → 深度"。
- **策略头样本质量是 AGZ 落地成败关键**：v10 的失败证明砍掉策略头不可行；v11 用 C++ MCTS 高吞吐 + 缓冲区滑动窗口 + D4 增强 + 人类棋谱先验来改善样本质量，而非改变网络范式。
- **编码/结构语义变更必须 fresh**：绝对→相对视角、通道/深度变化均使旧权重失效。
- **版本管理纪律**：一个版本一个结构（v6+v7 的拆分）、每步只动一个变量（v4/v5/v9）、试错版本保留原版可回退。
