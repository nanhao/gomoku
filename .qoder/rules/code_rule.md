trigger: model_decision
description: 编码时触发
---
- 开始编码前，确保你已阅读需求和设计方案，并已充分理解
- 使用 tdd，即测试驱动开发。测试优先于实现。先写测试，再写实现使测试通过。
- 写完代码确保测试用例通过。
- 代码有丰富的注释。
- 以最严格标准按照设计文档进行编码。如果发现有任何模糊或不妥之处，应该立刻暂停，向用户确认。
- 严禁写超长的函数、方法、类和文件。一个文件不允许超过 500 行。
- 严禁写重复代码。
- 写完代码检查一些 readme 需不需要更新。
- 写完代码立刻用 git 提交
- 修复 bug 后，要求输出详细的 bug 报告。并编写专门的测试用例覆盖该 bug
