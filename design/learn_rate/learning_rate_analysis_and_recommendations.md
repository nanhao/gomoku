# 学习率分析与优化建议书

## 背景

基于 cnn_v1 模型在 mini-batch 训练模式下的 loss 与梯度观测数据，对当前训练过程进行诊断，并提出优化建议。

---

## 1. 观测到的现象

### 1.1 Loss 曲线

- **起点**：~0.0047
- **终点**：~0.0010
- **趋势**：整体稳步下降，收敛良好

### 1.2 梯度范数（Grad Norm）曲线

- **前期**：~0.014，短暂下降至 ~0.010
- **后期（Step 60000 之后）**：持续增大至 ~0.017，且震荡剧烈
- **终点 spike**：接近 0.017

### 1.3 核心矛盾

> **Loss 在下降，说明方向正确；但梯度越来越大且震荡，说明步长相对于当前地形偏大。**

---

## 2. 根本原因分析

### 2.1 当前配置

| 配置项 | 当前值 |
|--------|--------|
| 优化器 | Adam |
| 学习率 | 0.001（固定） |
| Loss 函数 | L1 Loss（MAE） |
| 模型输出 | Softmax 概率分布（225维） |

### 2.2 Adam 的自适应局限性

Adam 为**每个参数**独立维护自适应步长：

```
Adam 实际步长 ≈ 全局学习率 / sqrt(该参数梯度的历史方差)
```

但 Adam **不会随训练进度全局衰减学习率**。当训练进入后期，loss landscape 变窄，固定学习率 0.001 变成了"大步"，导致参数在谷底附近**过冲（overshoot）**。

### 2.3 为什么梯度会越来越大

训练后期模型接近收敛区域时，可能进入**曲率更大的地形**（窄谷）。此时：
- 真实梯度方向非常陡峭
- 固定学习率导致参数越过谷底，撞到对面坡壁
- 下一次迭代又被梯度拉回
- 结果：参数在谷底两侧来回 bounce，梯度范数维持高位且震荡

### 2.4 两个相关概念

#### 梯度爆炸

某些 batch 的梯度突然变得极大（如从 0.01 → 1000），导致参数更新量失控，模型性能瞬间崩溃。这是**固定学习率在后期的大风险**。

#### Sharp Minimum（尖锐最小值）

Loss landscape 中窄而深的谷底。大学习率下参数容易在两侧陡壁间来回震荡，难以稳定收敛。小学习率才能让参数慢慢滑入谷底并停住。

---

## 3. 纠正的认识

关于学习率大小与 minimum 类型的关系：

| | 大学习率 | 小学习率 |
|--|---------|---------|
| **在 sharp minimum 附近** | 梯度大 → 一步迈过头 → **来回震荡** | 慢慢滑入谷底 → **稳定停住** |
| **在 flat minimum 附近** | 梯度小 → 但步长还是大 → **直接跨过** | 慢慢滑入谷底 → **稳定停住** |
| **最终结果** | **训练不稳定**，可能不收敛 | **收敛**，但可能停在任意 minimum |

> **正确理解**：小学习率确实更容易收敛到最近的 minimum（flat 或 sharp）。大学习率的问题不是"导致 sharp minimum"，而是"导致无法稳定收敛"。

---

## 4. 建议方案

### 方案 A：梯度裁剪（Gradient Clipping）—— 最快见效

在 `backward()` 后限制梯度上限，防止异常大梯度：

```python
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=0.02)
optimizer.step()
```

**优点**：
- 实现简单，一行代码
- 直接解决梯度爆炸风险
- 不改变收敛速度

**缺点**：
- 不解决震荡的根本原因（学习率仍然偏大）

### 方案 B：学习率衰减（Learning Rate Decay）—— 根本解决

#### B1. Step Decay（固定间隔衰减）

```python
scheduler = torch.optim.lr_scheduler.StepLR(optimizer, step_size=500, gamma=0.9)

for epoch in range(epochs):
    # ... 训练 ...
    scheduler.step()
```

- 每 500 epoch，学习率乘以 0.9
- 简单直接，推荐优先尝试

#### B2. ReduceLROnPlateau（按平台衰减）

```python
scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(
    optimizer, mode='min', factor=0.5, patience=100
)

for epoch in range(epochs):
    # ... 训练 ...
    scheduler.step(avg_loss)
```

- loss 连续 100 个 epoch 不下降时，学习率减半
- 更智能，但需要监控 loss

**优点**：
- 根本解决后期震荡问题
- 让参数能够"精细着陆"
- 有助于找到更 flat 的最小值

**缺点**：
- 需要调超参数（step_size、gamma）

### 方案 C：增大 Batch Size（辅助手段）

从 32 增大到 64 或 128：
- 梯度噪音减小
- 曲线更平滑
- 但内存消耗增加

**建议优先级**：B（学习率衰减）> A（梯度裁剪）> C（增大 batch size）

## 5. 预期效果

实施学习率衰减后，预期观察到：

| 指标 | 当前 | 预期 |
|------|------|------|
| Loss 终点 | ~0.0010 | 可能略降或持平 |
| Grad Norm 终点 | ~0.017（震荡） | **明显下降且平稳** |
| 曲线形态 | 梯度剧烈震荡 | **震荡幅度缩小，趋于稳定** |
| 训练稳定性 | 有梯度爆炸风险 | **更稳定** |

---

## 7. 结论

当前训练的核心问题：**固定学习率 0.001 在后期偏大**。

Adam 的自适应机制前期有效，但无法替代全局学习率衰减。建议：

1. **优先添加学习率衰减**（Step Decay 或 ReduceLROnPlateau）
2. **辅以梯度裁剪**作为安全网
3. **用 AI 内战和热力图验证**实际效果，而非仅看 loss 绝对值

> Loss 只是温度计，下棋赢不赢才是体温。
